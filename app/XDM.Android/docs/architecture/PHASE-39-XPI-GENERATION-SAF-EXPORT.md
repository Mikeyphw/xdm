# Phase 39 — Deterministic XPI generation and SAF export

Phase 39 turns the repository-owned Firefox source from Phase 38 into a reproducible package that can be generated by Gradle or by XDM Android itself.

## Shared package contract

The `:browser-extension` module owns `BrowserExtensionBuildConfig`, `BrowserExtensionPackageGenerator`, `BrowserExtensionPackageValidator`, `BrowserExtensionExportResult`, and `BrowserExtensionHash`. Gradle and the Android runtime call the same Kotlin generator and therefore produce the same bytes for the same configuration.

The archive contract requires sorted forward-slash entry names, no directory or traversal entries, a fixed local DOS timestamp of 1980-01-01 that is byte-identical across device time zones, STORED entries with precomputed CRC values, an exact required-file inventory, generated manifest/config/theme files, and SHA-256 verification.

Generated filenames follow:

```text
XDM-Android-Firefox-<extensionVersion>-<channel>-<theme>.xpi
```

Gradle outputs live under `browser-extension/build/outputs/xpi/` and are never committed.

## Android export transaction

`Settings → Browser extension` uses `OpenDocumentTree()` and persists read/write URI permission. The selected directory, default target, requested theme, and last verified export metadata survive process restarts through DataStore.

The export transaction is reviewable and failure-safe:

1. Generate the XPI into app cache.
2. Validate the archive, manifest, generated configuration, generated theme, and file inventory.
3. Verify temporary byte count and SHA-256.
4. Write a hidden `.part` document in the selected SAF tree.
5. Reopen and verify the staged document.
6. Promote by rename when supported, preserving the old file through a temporary backup.
7. For providers without rename support, snapshot an existing final XPI into verified app-cache storage before overwriting its stable URI.
8. Restore the previous XPI after a failed replacement; retain a verified provider/cache backup when restoration itself is refused.
9. Delete failed new documents, staging documents, obsolete backups, and temporary cache data whenever safe.
10. Persist filename, size, SHA-256, app version, extension version, theme, and generation time only after success.

A provider failure, revoked permission, or storage error never records a successful export. New partial documents are removed, while verified old bytes are preserved through provider or cache backup if the provider cannot complete restoration.

## Scope boundary

Phase 39 adds no top-level destination, WebView/browser runtime, Room migration, transfer-engine behavior, version change, or custom-scheme payload expansion. Theme colors are packaged as Dark and AMOLED presets for now; Phase 40 moves them to the shared app/extension theme-token contract and replaces the existing page card with the themed FAB.
